## 1. 目标结果

把当前 `0.1.0` 的“固定 plan/build 两阶段工作流”改造成 `0.2.0` 的透明 Claude Code Profile 启动器：

```bash
cmr kimi [任意 Claude Code 参数...]
cmr deepseek [任意 Claude Code 参数...]
```

最终可观察结果：

1. 用户先选择 Kimi 或 DeepSeek。
2. CMR 清理旧 Router 环境并注入所选 Profile。
3. CMR 把 Profile 选择器之后的 argv 原样交给 Claude Code。
4. Claude Code 按自身规则处理 `--continue`、`--resume`、`--fork-session`、`--permission-mode`、`--model`、`-p` 以及未来新增参数。
5. Kimi 可以规划也可以编码；DeepSeek 可以编码也可以规划。
6. `cmr plan` 与 `cmr build` 继续可用，但只是兼容别名。
7. Kimi 的费用信息保留为一行非阻塞提示，不再要求 `[y/N]` 二次确认。
8. 现有环境隔离、密钥脱敏、cwd、TTY、信号、退出码、Windows 适配和模型映射不得退化。

## 2. 原始问题与根因

### 2.1 当前 `0.1.0` 行为

- `cmr plan` 被描述为 Kimi 规划会话。
- `cmr build` 被描述为 DeepSeek 执行会话。
- `src/cli.js` 对 `plan/build` 后存在任何参数时直接报错。
- `src/commands/launch.js` 强制输出“新会话”和“不要用 `/model`”的限制性文案。
- Kimi 在交互终端多一次 `[y/N]` 确认。
- 产品文档把文件式交接写成唯一允许方式。

### 2.2 期望行为

CMR 的职责应当在 `spawn Claude Code` 后结束。用户仍按原生 Claude Code 习惯使用命令、会话、权限模式和工具，不需要为了切换 Provider 学习一套新的任务编排制度。

### 2.3 已确认根因

不是 Claude Code 缺少续聊能力，也不是 Provider 技术上必须绑定角色。根因是 CMR 把“推荐工作流”错误编码成了：

- Profile ID（`plan/build`）；
- CLI 参数拒绝；
- 启动提示和二次确认；
- 文档强制边界。

修复必须同时覆盖配置、解析、启动器、测试和文档。只删除一条报错属于局部补丁，会继续留下角色命名、别名、提示和验收冲突。

### 2.4 不需要解决的未知项

- 不需要知道旧会话原来使用哪个 Provider。
- 不需要保证任意 Provider 都支持旧会话里出现的模型名。
- 不需要解析 Claude Code 的会话文件。
- 不需要为每个 Claude Code 参数编写专用支持代码。

这些都通过“透明 argv + 用户显式选 Profile + Claude Code/Provider 自然反馈”解决。

## 5. 关键决策

| 决策 | 选择 | 为什么 | 禁止的替代方案 |
|---|---|---|---|
| 产品心智 | Provider/Profile 选择器 | 最接近“先切模型，再正常使用 Claude Code” | 固定 plan→build 流程 |
| 规范 ID | `kimi`、`deepseek` | 表达供应商，不表达任务角色 | 继续以 `plan/build` 为主 ID |
| 兼容 | `plan/build` 保留为别名 | 不破坏当前用户习惯或脚本 | 直接移除旧命令 |
| 参数 | 首 token 后的 argv 完全 opaque | 自动兼容当前和未来 Claude 参数 | 参数白名单、逐个解析 |
| 续聊 | 允许用户显式选择 | 会话自主权属于用户 | 跨 Provider 阻断或确认弹窗 |
| 跨 Provider | 允许但不自动 | 避免 CMR 冒充会话管理器 | Session Registry、Provider 推断 |
| 费用 | 一行提示、无确认 | 保留价格意识且不增加启动摩擦 | `[y/N]`、预算代理 |
| `/model` | 不拦截、不警告禁止 | 属于 Claude Code 原生行为 | 自建模型菜单或固定白名单 |
| 参数隐私 | 不记录任何透传 argv | `-p` 可能包含完整提示词 | 调试日志打印 argv |
| 交接 | 文件式 Brief 是推荐项 | 复杂任务更可审计 | 把 Brief 设为唯一允许方式 |
| 版本 | `0.2.0` | 用户可见行为与命令契约发生变化 | 继续标 `0.1.0` |

### 7.3 Profile 解析合同

在 `src/config/loader.js` 或同等配置层导出一个单一解析函数，建议签名：

```js
resolveProfile(profiles, selector) -> profile | null
```

规则：

1. `profile.id === selector` 时匹配。
2. 否则 `profile.aliases.includes(selector)` 时匹配。
3. 无匹配返回 `null`，不猜测、不模糊匹配、不忽略大小写。
4. 所有启动入口都使用同一函数；不在 `cli.js` 和 `launch.js` 各写一套映射。

### 7.4 配置校验合同

`validateConfigSet()` 必须额外保证：

- 恰好两个规范 ID：`kimi`、`deepseek`。
- 任一 Profile ID 不能重复。
- 任一别名不能重复。
- 别名不能等于任何 Profile ID。
- ID 和别名不能占用 CMR 管理命令保留字：

```text
help
--help
version
list
doctor
config
secret
```

- Kimi 必须包含 `plan`、`kimi-k3`；DeepSeek 必须包含 `build`、`deepseek-auto`。
- Provider、pricing、required environment 的既有严格校验保持不变。

保留字应在单一常量中定义并被校验复用；不要通过散落的条件分支碰巧规避冲突。

### 7.5 CLI 合同

推荐保持 `runCli(argv, options)` 外部签名不变，内部按以下决策树执行：

```text
argv 为空
  ├─ 交互 TTY：菜单返回 kimi / deepseek / doctor / exit
  └─ 非交互：打印 CMR usage，exit 0

argv 非空
  ├─ version/help/list/doctor/config/secret：按现有管理命令契约处理
  └─ 其他首 token：作为 Profile selector
       ├─ 可解析：launchProfile(selector, argv.slice(1), options)
       └─ 不可解析：ERROR unknown command/profile，exit 1
```

必要行为：

- `cmr help`、`cmr --help`：显示 CMR 帮助，不启动 Claude。
- `cmr kimi --help`：启动 Kimi 环境下的 `claude --help`。
- `cmr deepseek --version`：启动 DeepSeek 环境下的 `claude --version`。
- `cmr plan --continue`：等价于 `cmr kimi --continue`。
- `cmr build --permission-mode plan`：等价于 `cmr deepseek --permission-mode plan`。
- `cmr --continue`：首 token 无 Profile，不得猜 Kimi/DeepSeek，应报未知命令；用户必须明确先选 Profile。

`printUsage()` 推荐输出结构：

```text
Claude Model Router 0.2.0

Usage:
  cmr                                Show the profile menu
  cmr kimi [claude args...]          Start Claude Code with Kimi K3
  cmr deepseek [claude args...]      Start Claude Code with DeepSeek Auto
  cmr plan [claude args...]          Alias for kimi
  cmr build [claude args...]         Alias for deepseek
  ...existing management commands...

Claude Code arguments after the profile are passed through unchanged.
```

不要复制 Claude Code 的完整帮助；它会变化，应该通过 `<profile> --help` 查看。

### 7.6 `launchProfile()` 合同

目标签名：

```js
launchProfile(profileSelector, claudeArgs = [], options = {}) -> Promise<number>
```

执行顺序：

1. 验证 `claudeArgs` 是数组；不要修改调用者数组。
2. `loadConfigSet(options)`。
3. 用统一解析函数解析 ID/别名；无匹配抛 `unknown profile: <selector>`。
4. 找 Provider、pricing、secret，保持当前缺密钥错误和脱敏方式。
5. 高费用 Profile 只向 stderr 写一行。该行可同时含显示名、价格摘要和 `verifiedOn`，不得询问输入。
6. 不输出“starts a new session”“do not use /model”“planning only”“build only”。
7. 构建子进程环境副本。
8. 调用 `runClaude({ ..., executableArgs, claudeArgs })`。

删除 `createInterface` import 与 `confirmHighCost()`；不要留下从未调用的兼容死代码。删除函数代码不等于删除文件，不触发 Gate R。

### 7.7 `runClaude()` 与 argv 合同

目标签名新增：

```js
runClaude({
  env,
  cwd,
  executable,
  executableArgs = [],
  claudeArgs = [],
  platform,
  spawnImpl,
  processLike,
  stdio
})
```

最终传给 `runChild()` 的数组顺序必须是：

```js
[...spec.args, ...executableArgs, ...claudeArgs]
```

原因：测试使用 `node <fake-claude.js> [用户参数]`，fixture 路径必须先于用户参数；真实 `claude` 的 `executableArgs` 为空。两个数组语义不同，不得把用户参数复用为 `executableArgs`。

禁止：

- `.join(" ")`；
- 构造 Shell 命令字符串；
- JSON stringify 后传一个参数；
- 删除未知 flag；
- 对 `--resume` 猜测是否有值；
- 日志打印 `claudeArgs`。

### 7.8 输出与隐私合同

CMR 可以输出：Profile 显示名、Provider、价格摘要、核验日期、公开模型映射、configured/missing。

CMR 不得输出：

- `claudeArgs` 数组；
- `-p/--print` 后的提示词；
- resume session ID；
- 参数中的本机路径；
- Secret 值或完整环境。

即使启动失败，错误也只能说明可执行文件、Profile 或 Secret 状态，不得把完整启动命令附在异常中。

## 9. `0.2.0` 用户场景合同

### 9.1 最简单启动

```bash

```

```bash

```

进入后所有操作与正常 Claude Code 相同。用户不需要先产 Brief，也不需要按 plan→build 顺序。


含义是“用现在选择的 Profile 环境，让 Claude Code 继续它认为的当前目录最近会话”。CMR 不替用户核对旧会话 Provider。

`--resume` 是否显示选择器、`<session-id>` 的格式和查找规则由当前 Claude Code 决定。

```bash
cmr deepseek --permission-mode plan
```

这说明 DeepSeek 也可以做规划；`plan` 兼容别名与 Claude Code 的 `--permission-mode plan` 是两件事：

```bash
cmr plan --permission-mode plan
```

前一个 `plan` 是 Kimi Profile 兼容别名，后一个 `plan` 是 Claude Code 权限模式的值。

### 9.6 非交互执行

```bash
cmr kimi -p "分析这个项目"

```

CMR 不记录 prompt；真实执行可能产生 Provider 用量。

```bash

cmr deepseek --model <model>
```

CMR 不阻止。若当前 Provider 不支持该模型，错误来自 Claude Code/Provider。恢复默认行为的方法是退出并不带 `--model` 重新运行所选 Profile；不要承诺任意 Anthropic 官方模型名能在第三方 Provider 使用。

### 9.8 兼容旧命令

```bash
cmr plan       # alias for cmr kimi

```

别名也支持全部参数透传。

## 10. 风险与控制

| 风险 | 触发信号 | 控制/回退 |
|---|---|---|
| 只移除 CLI 拒绝，但 launch 未传 argv | fake Claude `args=[]` | 按 CLI→launch→launcher 全链路逐层断言 |
| alias 与管理命令碰撞 | `cmr list` 启动 Profile | validator 保留字和跨集合唯一性测试 |
| Kimi/DeepSeek 映射在重命名时漂移 | Profile 快照差异 | 逐键对照旧值；差异即停止 |
| prompt/session ID 泄漏 | 哨兵出现在输出 | 不记录 argv；出现即 Blocker，清除证据原文 |
| 参数被 Shell 重新解释 | 空格/中文/`--value` 不相等 | argv 数组；Windows 分支单测，不用字符串命令 |
| `executableArgs` 与用户参数顺序错误 | Node 把 flag 当自身参数 | 明确顺序 `spec + executable + claude` |
| 旧脚本失效 | `cmr plan/build` 未解析 | 数据别名 + 双入口等价测试 |
| 仍有任务角色限制 | 帮助出现 only planning/build | 中性 Profile 文案 + 文档全文搜索 |
| Kimi 启动仍需确认 | TTY 等待输入 | 删除 readline/confirmHighCost，输出测试 |
| 跨 Provider resume 被误解为自动兼容 | 用户期望 CMR 修复旧模型名 | 文档说明允许但不保证；不建 Registry |
| 全局命令变更被误认为需重装 | 试图 npm install -g | 当前安装是仓库链接；只读 `command -v cmr` 验证 |
| 执行者改写 0.1 历史 | docs09 被重构 | docs09 只保留历史；0.2 证据回写本文 |
| 真实验收产生费用或修改会话 | 执行 `-p/continue/resume` | Gate T；默认只做 fake 测试和真实 help/version |

回退原则：当前无 Git。Luna 在动手前应在回复中记录基线文件清单和关键版本，不在仓库内创建备份副本。若实现失败，优先用小补丁恢复单个文件；任何删除/覆盖式回退仍受用户红线约束。不要运行 `git reset` 或创建临时“old/bak”冗余文件。

### 14.1 独立发现与修复

| 级别 | 根因 | 修复 |
|---|---|---|
| Blocker | Windows `.cmd` 使用 `shell: true`，会让 opaque 用户参数再次经过 Shell 解释 | 改为显式启动 `cmd.exe /d /c`，`shell: false`；加入含 Shell 元字符的 argv 回归 |
| Major | `child.killed` 只表示发过信号，导致第二次 Ctrl+C 被吞 | 按 `exitCode/signalCode` 判断存活，重复转发信号直到子进程退出 |
| Major | 隐藏 Secret 输入在 EOF/stream error 时永久等待 | 完整监听 `end/close/error`，所有出口恢复终端 raw mode 并移除监听器 |
| Major | 日期和 Profile 语义校验不严，可接受不存在日期或 Kimi/DeepSeek 交叉绑定 | 严格日历校验、固定集合和 Provider/Pricing 绑定校验 |
| Major | macOS Secret Store 会吞目录权限收紧失败；已存损坏值校验弱 | POSIX 权限失败即停止，拒绝空白边界、换行、NUL、超长及损坏 Schema |
| Major | `.cmd` 版 Claude 在 Doctor 中无法可靠读取版本 | Doctor 与启动器共用安全 Windows spawn spec |
| Major | 迁移在双文件已替换后 chmod 失败时不会恢复 | 对所有已替换文件执行备份恢复，并显式报告不完整回滚 |
| Minor | 前缀重叠的两个 Secret 可能先替换短值而残留长值后缀 | 脱敏前按 Secret 长度降序去重 |
| Minor | 管理命令静默忽略额外参数；架构目录树列出不存在的 `secret.js` | 严格拒绝额外参数并校正文档结构 |
