## 1. 结论先行

### 1.1 两个 GLM Profile 同步升级

本轮绑定以下目标：

| Profile | Opus | Sonnet | Haiku | 子 Agent | 费用通道 |
|---|---|---|---|---|---|
| `glm` | `glm-5.3[1m]` | `glm-5.3[1m]` | `glm-5.3-flash[1m]` | `glm-5.3-flash[1m]` | GLM Coding Plan subscription quota |
| `glm-api` | `glm-5.3[1m]` | `glm-5.3[1m]` | `glm-5.3-flash[1m]` | `glm-5.3-flash[1m]` | GLM 标准 API 直接按量付费 |

`glm-api` 必须一起升级，理由不是“两个 Profile 看起来一致”，而是旧合同的前提已经失效：

1. `docs/18` 在 2026-08-16 记录的“GLM-5.3 标准 API 尚未上线”已过期；当前官方 Claude API 兼容文档已使用 `glm-5.3`，GLM-5.3 模型 API 已可用。
2. `glm-5.3-flash` 当前有正式模型 ID、API 可用声明、Anthropic 兼容接入链路与公开按量价格。
3. 若只升级 `glm`，`glm-api` 将继续停留在 5.2/4.7，并继续显示只覆盖旧模型组合的价格事实，形成不必要且误导的能力分叉。

### 1.2 保持两条鉴权与费用边界

两条通道共享 Base URL，但不得合并 Provider、Secret 或鉴权变量：

```text
glm
  baseUrl=https://open.bigmodel.cn/api/anthropic
  authVariable=ANTHROPIC_AUTH_TOKEN
  secretId=glm
  billing=GLM Coding Plan subscription quota

glm-api
  baseUrl=https://open.bigmodel.cn/api/anthropic
  authVariable=ANTHROPIC_API_KEY
  secretId=glm-api
  billing=GLM standard API pay-as-you-go
```

CMR 不检测 Key 类型、不查询余额或额度、不自动 fallback、不在认证/欠费失败后重试到另一通道。每次启动仍只允许注入当前 Provider 的一个鉴权变量。

### 1.3 本轮不新增 `glm-flash` 全 Flash Profile

本轮仅升级两个现有入口，不新增全槽位 Flash Profile。原因：用户当前目标是复用 DeepSeek Auto 的主模型/轻量模型分工；新增正式 Profile 会扩大菜单、别名、文档和长期维护面，但不是实现该目标的必要条件。

如果后续确实需要“主会话直接看图”，应单独立项评估一个全槽位 `glm-5.3-flash[1m]` Profile。不得把内容识别、图片检测或运行时动态路由塞进本轮。

## 2. 官方事实复核（2026-08-26）

主来源：

- [智谱新模型发布](https://docs.bigmodel.cn/cn/update/new-releases)：2026-08-26 发布 GLM-5.3-Flash，声明原生多模态。
- [GLM-5.3-Flash 模型页](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)：模型代码 `glm-5.3-flash`；模型 API 已可用；支持文本、图片、视频与文件，1M 上下文；支持 Function Calling、上下文缓存与结构化输出；思考默认持续开启。
- [GLM Coding Plan 概览](https://docs.bigmodel.cn/cn/coding-plan/overview)：当前套餐支持 GLM-5.3 与 GLM-5.3-Flash；Flash 的套餐额度消耗倍率低于完整模型。
- [GLM Coding Plan 模型切换](https://docs.bigmodel.cn/cn/coding-plan/latest-model)：官方给出 Claude Code 全 Flash 映射，Opus/Sonnet/Haiku 均可使用 `glm-5.3-flash[1m]`；这证明该值是官方 Claude Code 选择层值。
- [GLM Coding Plan 快速开始](https://docs.bigmodel.cn/cn/coding-plan/quick-start)：Anthropic 兼容 Base URL 仍为 `https://open.bigmodel.cn/api/anthropic`。
- [智谱 Claude API 兼容](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)：当前示例已由旧的 GLM-5.2 更新为 `glm-5.3`，标准 API 使用同一 Anthropic 兼容 Base URL 与 `ANTHROPIC_API_KEY`/`x-api-key` 语义。
- [智谱模型价格](https://bigmodel.cn/pricing)：GLM-5.3 与 GLM-5.3-Flash 均已有标准 API 按量价格。
- [Claude Code 模型配置](https://code.claude.com/docs/en/model-config)：支持 `ANTHROPIC_DEFAULT_OPUS_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_HAIKU_MODEL` 与 `CLAUDE_CODE_SUBAGENT_MODEL`；最后一项会统一覆盖全部子 Agent 的模型选择。

### 2.1 可直接采用的官方事实

1. `glm-5.3-flash` 是正式模型代码，不使用发布日期前的猜测名或别名。
2. `glm-5.3-flash[1m]` 是智谱当前 Claude Code 指南明确使用的选择层值。
3. Coding Plan 当前同时支持 `glm-5.3` 与 `glm-5.3-flash`。
4. 标准 API 的 `glm-5.3` 已上线；`glm-5.3-flash` 模型页明确模型 API 已可用。
5. 两条现有 Provider 的 Base URL 与鉴权变量没有变化，不需要新增 Provider 或 Secret。
6. Claude Code 官方支持用 `CLAUDE_CODE_SUBAGENT_MODEL` 给全部子 Agent 设置单独模型。

### 2.2 必须标为 CMR 产品决策的部分

以下不是智谱或 Anthropic 发布的一份完整预设，不能写成“官方 Auto 模式”：

1. Opus/Sonnet=`glm-5.3[1m]`、Haiku/Subagent=`glm-5.3-flash[1m]` 的混合组合。
2. Coding Plan 与标准 API 两个现有 CMR Profile 使用相同模型槽分工。
3. 用 Flash 承担轻量请求、子 Agent 与可能的视觉任务，同时保留完整 5.3 作为主会话模型。

官方分别证明了模型、端点、Claude Code 模型变量和各费用通道可用；CMR 负责把这些官方能力组合成固定 Profile。因此自动化测试能证明环境注入正确，但不能替代真实 Provider 验收。

### 2.3 标准 API 证据强度与发布门槛

标准 API 的支持证据来自多份官方页面的组合：Claude API 兼容页证明标准通道当前支持 `glm-5.3`，Flash 模型页证明 `glm-5.3-flash` 模型 API 可用，Coding Plan 模型切换页证明 `[1m]` Claude Code 选择值。当前没有一页官方文档逐字给出“标准 API Key + 本文件四槽混合映射”的完整配置。

结论是：可以进入实现，但 `glm-api` 不能只凭假 Claude 快照宣告发布 PASS。发布前必须在用户明确授权下完成标准 API Key 的真实主请求、Haiku/Flash 请求、子 Agent、图片输入与费用明细回读；任何一项不成立，都必须停止并先更新本文件与 `docs/07`，不得临时换 Key、降级到旧模型或混入 Coding Plan 通道。

## 3. 绑定行为合同

### 3.1 `glm` Coding Plan

Profile 身份、aliases、Provider、Secret、cost notice 与 entitlement 保持不变。环境必须精确为：

```text
ANTHROPIC_DEFAULT_OPUS_MODEL=glm-5.3[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL=glm-5.3[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL=glm-5.3-flash[1m]
CLAUDE_CODE_SUBAGENT_MODEL=glm-5.3-flash[1m]
CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
API_TIMEOUT_MS=3000000
```

### 3.2 `glm-api` 标准 API 按量付费

Profile 身份、alias `glm-payg`、Provider、Secret 与 cost notice 保持不变。环境必须与 §3.1 的模型/运行参数完全相同；唯一费用与鉴权差异来自 Provider/Profile 元数据：

```text
provider=glm-api
authVariable=ANTHROPIC_API_KEY
secretId=glm-api
costNotice=payg
pricingRef=glm-5.3
```

### 3.3 明确不设置的变量

两个 Profile 均不得因本轮自行增加：

- `ANTHROPIC_MODEL`
- `CLAUDE_CODE_EFFORT_LEVEL`
- Fable 映射
- Tool Search 开关
- 任何图片识别、提示词分类、动态路由或 fallback 变量

不设置 `ANTHROPIC_MODEL` 的目的，是保持现有 GLM Profile 的 Claude Code 语义与最小改动边界；默认主槽由 Opus/Sonnet 映射承担，不在本轮引入额外全局覆盖。

### 3.4 子 Agent 覆盖的语义

`CLAUDE_CODE_SUBAGENT_MODEL=glm-5.3-flash[1m]` 是强制的全局子 Agent 覆盖。它意味着即使某个内建/自定义子 Agent 原本请求 Opus 或在 frontmatter 中声明其他模型，启动于这两个 Profile 下时仍会统一使用 Flash。

这是本轮预期行为，不是兼容性副作用。实现与用户文档必须明确写出；若后续需要保留单个 Agent 的独立模型声明，应另行改变产品合同，不能在实现中静默例外。

### 3.5 多模态能力边界

本映射不是内容路由器：

- 主会话默认仍使用文本模型 `glm-5.3[1m]`，向主会话直接附图不会自动切到 Flash。
- 显式选择 Haiku 时会命中 Flash，但是否以及如何从当前 Claude Code 版本传递图片，仍需真实验收。
- 子 Agent 使用 Flash 不代表 Claude Code 会自动把主会话图片委派给子 Agent；委派行为由 Claude Code 和提示决定。
- CMR 不检查消息中是否含图片、视频或文件，不重写请求内容，也不代理 Anthropic 消息。

## 4. 标准 API Pricing 合同

### 4.1 新增当前模型族价格记录

新增 `config/pricing/glm-5.3.json`，建议使用与 `deepseek-v4.json` 相同的模型族价格树：

```json
{
  "id": "glm-5.3",
  "displayName": "GLM-5.3 standard API family",
  "model": "glm-5.3",
  "currency": "CNY",
  "unit": "per_million_tokens",
  "prices": {
    "glm-5.3": {
      "inputCacheHit": 2,
      "inputCacheMiss": 8,
      "output": 28
    },
    "glm-5.3-flash": {
      "inputCacheHit": 0.23,
      "inputCacheMiss": 0.8,
      "output": 2.8
    }
  },
  "contextWindowTokens": 1000000,
  "verifiedOn": "2026-08-26",

```

`glm-api.pricingRef` 从 `glm-5.2` 改为 `glm-5.3`。启动警告必须同时覆盖本 Profile 实际映射的完整模型与 Flash 两档价格，不能继续输出“GLM-5.2”或笼统的“其他模型价格可能不同”。

### 4.2 限时促销不写入长期配置

2026-08-26 官方动态价格页同时显示 GLM-5.3-Flash 限时两周五折价：缓存命中 0.115、输入 0.4、输出 1.4 CNY/百万 tokens；对应公开原价为 0.23/0.8/2.8。

当前 Pricing schema 没有生效/失效日期，也没有自动在线刷新。长期配置必须记录原价 0.23/0.8/2.8，限时价只记录在本文与当日核验证据中。若实施 Agent 要让运行时展示促销价，必须先提出带有效期和过期行为的 schema 方案，经项目负责人确认后再改；不得把两周促销值直接写死。

### 4.3 保留旧 GLM-5.2 Pricing 文件

本轮不删除 `config/pricing/glm-5.2.json`。它可以作为仍有效的历史模型价格事实保留在 catalog 中，但两个现行 GLM Profile 都不得继续引用它。删除文件属于独立清理动作，需要项目负责人另行批准。
