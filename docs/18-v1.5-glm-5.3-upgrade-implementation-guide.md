# 18 — GLM-5.3 Coding Plan 升级：GLM53-1 至 GLM53-4 实施指导书

状态：**RELEASED — GLM53-1 至 GLM53-4 实施完成并随 `1.5.0` 于 2026-08-18 公开发布**
制定日期：2026-08-16
目标：在不破坏未发布的 `1.5.0` Kimi Code 候选的前提下，将 `cmr glm` 的 Coding Plan 模型升级为 GLM-5.3。

> 本文件是本轮升级的现行合同。`docs/14`、`docs/15`、`docs/16` 保留为 `1.4.0` GLM-5.2/标准 API 的历史实施与发布证据，不得全局替换、回写或伪造为 GLM-5.3 证据。`docs/17` 的 Kimi Code 候选也不属于本轮功能范围。

## 1. 结论先行

本轮只改变 Coding Plan 的 `glm` Profile；标准 API 的 `glm-api` 暂时保持 GLM-5.2。

```text
cmr glm / cmr glm-5.3 / cmr glm-5.2 / cmr glm-plan
  -> 当前 glm Coding Plan Profile
  -> Opus/Sonnet=glm-5.3[1m]
  -> Haiku=glm-4.7

cmr glm-api / cmr glm-payg
  -> 独立 glm-api 标准 API Profile
  -> Opus/Sonnet=glm-5.2[1m]
  -> Haiku=glm-4.7
  -> pricingRef=glm-5.2
```

两条 GLM 通道仍然独立：`glm` 只使用 `ANTHROPIC_AUTH_TOKEN` 与 `glm` Secret；`glm-api` 只使用 `ANTHROPIC_API_KEY` 与 `glm-api` Secret。CMR 不检测 Key 类型、不自动 fallback、不重试到另一条费用通道，也不发送真实 Provider 请求。

## 2. 官方事实复核（2026-08-16）

主来源：

- [GLM-5.3 模型页](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)
- [智谱 Claude Code 接入](https://docs.bigmodel.cn/cn/guide/develop/claude)
- [智谱 Claude API 兼容](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)
- [GLM-5.2 模型页](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.2)
- [智谱产品价格](https://bigmodel.cn/pricing)
- [Claude Code Environment Variables](https://code.claude.com/docs/en/env-vars)
- [Claude Code Model Configuration](https://code.claude.com/docs/en/model-config)

本轮采用的事实与边界：

1. 智谱 GLM-5.3 模型页声明 GLM Coding Plan 已全量上线 GLM-5.3；GLM-5.3 支持 1M 上下文，最大输出 128K。
2. 同一页面明确声明 GLM-5.3 模型 API 将于近期上线；Anthropic Message 端点虽被列为未来支持协议，但这不等于当前标准 API 已可用。
3. 当前智谱 Claude Code 接入示例仍以 GLM-5.2 为最新示例，并给出 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_DEFAULT_*_MODEL`、compact、timeout 和 disable-nonessential 配置。GLM53-2 将 Coding Plan 的 Opus/Sonnet 选择值替换为 GLM-5.3 选择值，保留已绑定的 `glm-4.7` Haiku 与运行参数。
4. 当前智谱 Claude API 兼容页面仍以原生 `glm-5.2` 为标准 API 示例，并继续使用 `ANTHROPIC_API_KEY`/`x-api-key` 语义。GLM53-4 因此明确保持 `glm-api` 的 `glm-5.2[1m]`、`glm-4.7` 与现有 2/8/28 CNY/M Pricing。
5. `glm-5.3[1m]` 是 Claude Code 选择层值；CMR 不自行剥离 `[1m]`，也不建立 API 代理转换层。标准 API 的原生模型字段继续是 `glm-5.2`，直到新的 API 事实和迁移卡另行批准。

若官方页面在后续发布前改变，必须先更新本文件与 `docs/07`，再调整配置和测试；不得只改 JSON。

## 3. 绑定配置合同

### 3.1 `glm` Coding Plan

Provider 保持：

```text
id=glm
baseUrl=https://open.bigmodel.cn/api/anthropic
authVariable=ANTHROPIC_AUTH_TOKEN
secretId=glm
```

Profile 目标：

```text
id=glm
aliases=["glm-5.3", "glm-5.2", "glm-plan"]
displayName=GLM-5.3 Coding Plan
costNotice=subscription
entitlementRef=glm-coding-plan-membership
```

环境必须精确为：

```text
ANTHROPIC_DEFAULT_OPUS_MODEL=glm-5.3[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL=glm-5.3[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL=glm-4.7
CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
API_TIMEOUT_MS=3000000
```

不得为本轮添加 `ANTHROPIC_MODEL`、Fable、Subagent、Effort、Tool Search 或其他未绑定变量。`glm` 子进程只能有 `ANTHROPIC_AUTH_TOKEN`，不能残留 `ANTHROPIC_API_KEY` 或任何混合大小写变体。

### 3.2 `glm` 的 subscription-quota entitlement

新增 `config/entitlements/glm-coding-plan-membership.json`，使用通用权益话术，不引用 `glm-5.2` Pricing，不承诺无限额度、不推断剩余额度，也不承诺不会产生额外费用。Profile 的商业元数据必须满足 `pricingRef XOR entitlementRef`，本 Profile 只能有 `entitlementRef`。

运行时提示由 entitlement 数据驱动，至少表达：当前使用 GLM Coding Plan subscription quota；额度、套餐规则和任何额外使用费用以智谱账户与官方规则为准。不得出现 2/8/28 CNY/M 或“本次会话费用”。

### 3.3 `glm-api` 标准 API

本轮不迁移标准 API：

```text
displayName=GLM-5.2 API (Pay-as-you-go)
authVariable=ANTHROPIC_API_KEY
secretId=glm-api
pricingRef=glm-5.2
Opus/Sonnet=glm-5.2[1m]
Haiku=glm-4.7
prices=cache hit 2 / input 8 / output 28 CNY/M
```

`glm-api` 继续显示标准 API 直接按量计费提示，提示值来自既有 `config/pricing/glm-5.2.json`。GLM53-4 不新增 `glm-5.3` Pricing、不改 `glm-api` 模型、不改 `ANTHROPIC_API_KEY` 边界。
