# 23 — v1.8.1 自更新完整性校验查找修复：HF-1 至 HF-3 实施指导书

状态：CANDIDATE（发布后翻转为 RELEASED）。
关联版本：`1.8.1`（基于 `1.8.0` 门禁 commit `7929582` 之后的 main）。
事故级别：公开发布回归——自 `1.7.0` 起，真实环境完整 `cmr update`（非 `--check`）在所有平台必然失败；fail-closed 设计保证了旧版本完好，无损坏安装，但自动更新通道实际不可用。

## 1. 结论先行

`1.7.0` 引入的 SHA256SUMS 资产完整性校验（`docs/21` SC-2）按 **npm pack 报告的 tarball 文件名** 在 SHA256SUMS 中查找条目；而真实 npm（本仓验证：npm 11.19.0 / Node 26.7.0，macOS）对远程 tarball URL 规格输出 `<name>-<version>.tgz`（如 `claude-model-router-1.8.0.tgz`），发布资产与 SHA256SUMS 条目则是固定名 `claude-model-router.tgz`。查找键与发布条目永不一致 → `ERROR integrity check unavailable: published SHA256SUMS has no entry for the release asset`。修复：查找键改为固定资产 URL 的 basename（`LATEST_RELEASE_ASSET_URL` 末端段），与 npm 的命名行为解耦；npm 写盘字节与发布资产逐字节一致（已实测 sha256 相同），故对 npm 落盘文件做哈希、对资产条目做比对的语义不变。

存量用户免重装：v1.8.1 起 SHA256SUMS 常设第二条同摘要别名条目（npm 落盘名，见 HF-4），使 ≤1.8.0 的旧 updater 照常 `cmr update` 即自愈到新版——不要求任何手动重装。

发布门禁缺口是本回归漏出的直接原因：`docs/16`/`docs/17` 的发布配方只要求 `cmr update --check`，而 `--check` 路径不做完整性校验（`checkLatest` 不调用 `verifyReleaseIntegrity`），真实完整 `cmr update` 自 `1.7.0` 起从未对真实 GitHub Release 执行过。本版发布门禁必须补一次隔离 prefix 的真实完整 `cmr update`（HF-3）。

## 2. 事件与根因登记（2026-08-27）

### 2.1 现象

- 用户报告：一台已安装 CMR 的 Windows 机器执行 `cmr update` 失败，报 `ERROR integrity check unavailable: published SHA256SUMS has no entry for the release asset`。
- 已安装版本 ≤ `1.7.x`（若已装 `1.8.0`，`plan === "same"` 在校验前提前返回，不会触达该报错）。
- 旧版本保持完好（校验发生在 install 之前，fail-closed 生效），无回滚、无损坏。

### 2.2 根因链条

1. `packLatestRelease` 以 `LATEST_RELEASE_ASSET_URL` 为规格运行 `npm pack <url> --json`，npm 将远程资产落盘为清单名 `claude-model-router-<version>.tgz` 并在 JSON `filename` 中报告该名。
2. `verifyReleaseIntegrity` 用 `path.basename(tarballPath)`（即 npm 报告的 `claude-model-router-1.8.0.tgz`）在 SHA256SUMS 中查条目。
3. 发布侧 SHA256SUMS 条目名是固定资产 `claude-model-router.tgz`（与资产同名，`docs/16` 配方）。
4. 查无条目 → `throwUpdate("integrity check unavailable", ...)`。平台无关：任何 npm 对远程 tarball URL 都按清单命名，macOS 同样失败；用户恰好在 Windows 机器上首次触发。
5. 测试为何未拦截：`tests/update.test.js` 的 `fakeReleaseSums` 与假 npm runner 共用同一 `FAKE_CANDIDATE_FILENAME`（`claude-model-router-1.3.0-candidate.tgz`），自洽的假世界掩盖了真实两侧命名分歧。
6. 发布门禁为何未拦截：门禁只跑 `cmr update --check`，该校验仅存在于完整 update 事务路径。

### 2.3 实测证据（2026-08-27，macOS，npm 11.19.0 / Node v26.7.0）

- `curl -L <latest 资产 URL>` 与 `npm pack <同一 URL>` 产物 sha256 相同：`b71a5102c9d1e43dd1d16666ad8147b0c89665422155552bac0e39629af05b94`，与发布 SHA256SUMS 条目一致——npm 对远程 tarball 流式原样落盘，不重打包。
- `npm pack --json` 报告 `filename: "claude-model-router-1.8.0.tgz"`。

### 2.4 限制声明

- npm「原样落盘」是实测行为而非承诺合同。若未来 npm 改为重打包，本修复会以 `integrity verification failed`（哈希不匹配）fail-closed，不会放过被篡改资产；这与本仓安全立场一致。
- 「latest 翻转」TOCTOU 在 npm 下载与 SHA256SUMS 拉取之间理论上存在；表现为哈希不匹配或条目缺失，均 fail-closed，重试即恢复。维持既有语义，不在本 hotfix 扩围。

## 3. 绑定行为合同（修复后语义）

`verifyReleaseIntegrity({ tarballPath })`：

1. 拉取 `LATEST_RELEASE_SUMS_URL` 文本（现有超时/大小上限不变）。
2. 以 `LATEST_RELEASE_ASSET_URL` 的 basename（`claude-model-router.tgz`）为唯一查找键解析条目；查无 → `integrity check unavailable: published SHA256SUMS has no entry for the release asset`。
3. 对 `tarballPath`（npm 落盘文件）计算 sha256，与条目比对；不一致 → `integrity verification failed`。
4. 查找键与 npm 报告的 `filename` 完全解耦；npm 侧命名变化不影响校验。

发布侧合同（HF-4）：v1.8.1 起 SHA256SUMS 含两条**同摘要**条目——固定资产名与该版本 npm 落盘名（如 `claude-model-router-1.8.1.tgz`）。新客户端命中第一条；≤1.8.0 旧客户端按 npm 文件名命中第二条并照常完成逐字节校验。别名条目为常设项，任何未来版本同理。

## 4. 任务卡

### HF-1 — 查找键修复（`src/commands/update.js`）

- 将 `parseReleaseSumsEntry(text, path.basename(tarballPath))` 改为以 `LATEST_RELEASE_ASSET_URL` 的 basename 查找；同步更新相邻注释，说明 npm 清单命名与资产固定命名的分歧及「npm 原样落盘、按资产条目比对」的依据。
- 不改错误文案、不改 `verifyReleaseIntegrity` 其余行为。

### HF-2 — 测试镜像真实分歧（`tests/update.test.js`）

- `fakeReleaseSums` 条目名改为 `claude-model-router.tgz`，假 npm runner 候选文件名保持 `claude-model-router-<version>-candidate.tgz` 不变——所有既有正向用例从此覆盖真实分歧。
- 哈希不匹配用例（`update refuses to install a release asset that fails SHA256SUMS verification`）的假 SHA256SUMS 条目同步改用资产名，确保仍走到 mismatch 分支。
- 新增回归用例：SHA256SUMS 只含按 npm 版本化命名的条目（修复前的错误查找键）时，必须报 `has no entry for the release asset` 且零 install 调用——钉死查找键。

### HF-3 — 发布门禁补强（本指导书 §5，作用于 v1.8.1 及以后发布）

- 发布后回读在既有 exact/latest 双 URL + 隔离 prefix 安装 + `cmr update --check` 之外，新增：在隔离 prefix 安装一个旧稳定版（如 `1.7.x` 或当前机器上的既有旧版）后执行一次**真实完整 `cmr update`**，断言成功升级且新版本可运行。
- 既有已发布版本（≤ `1.8.0`）的自动更新通道失效是既成事实；HF-4 别名条目使其照常 `cmr update` 自愈，手动安装仅作兜底（见 §6）。

### HF-4 — SHA256SUMS 同摘要别名条目（发布配方，v1.8.1 起常设）

- 自 v1.8.1 起每个 Release 的 SHA256SUMS 同时发布两条相同摘要的条目：固定资产名 `claude-model-router.tgz` 与该版本 npm 落盘名 `claude-model-router-<版本>.tgz`。
- 目的：≤1.8.0 的旧 updater 按 npm 文件名查找，命中别名后仍做逐字节哈希比对（字节与资产一致，必然通过），随后正常安装新版——存量用户（含全部 Windows 安装）`cmr update` 一次即自愈，免除手动重装。摘要相同，不引入任何绕过完整性校验的路径。
- 常设理由：晚更新的存量旧客户端在任意未来版本上同样自愈；移除别名只会重新制造本 §2 登记的故障。个别 npm 若按 URL basename 落盘，旧客户端直接命中资产条目，同样通过。
- 测试侧：`fakeReleaseSums` 镜像两行发布格式；HF-3 门禁即别名机制的端到端验收。

4. 门 3 — 发布后回读：exact/latest 双 URL 回读（含 SHA256SUMS 两行断言）；隔离 prefix 安装 `1.8.1`；HF-3 新增的旧版（`1.8.0`）→`1.8.1` 真实完整 `cmr update` 自愈成功；`cmr update --check` 报 already-current。

## 6. 受影响机器的恢复指引

主路径（自动，免重装）：HF-4 别名条目发布后，已装 `1.7.0`–`1.8.0` 的机器照常执行 `cmr update` 即自愈升级到 `1.8.1`，此后更新通道恢复。旧版本本身功能完好，仅更新通道受损，无紧急处置必要。

兜底路径（仅当自动路径意外失败，如个别 npm 对远程 tarball 的落盘命名异常）：手动安装一次——

```powershell
npm install --global https://github.com/zouerdong/ai-model-router/releases/latest/download/claude-model-router.tgz
```
