## 0. 一页结论

### 0.1 本轮要解决的问题

当前 `cmr kimi` 连接的是 Kimi 开放平台按量 API：

```text
Base URL=https://api.moonshot.cn/anthropic
Auth=ANTHROPIC_AUTH_TOKEN / Bearer
Secret ID=kimi
费用=开放平台按 Token 付费
```

Kimi Code 是另一条独立产品通道：

```text
Base URL=https://api.kimi.com/coding/
Auth=ANTHROPIC_API_KEY / X-Api-Key
Secret ID=kimi-code
费用=会员/订阅额度；启用 Extra Usage 后可能继续按量扣费
```

两条通道的 Key、端点、权益与账单不互通。因此 `1.5.0` 必须新增独立 `kimi-code` Provider 和 Secret，不能改绑、覆盖或自动识别现有 `kimi`。

### 0.2 `1.5.0` 首批候选入口

首批只实现三个候选入口：

| 规范 Profile | 兼容别名 | Claude Code 选择值 | 上游原生模型 | 上下文 | 最低已知权益 |
|---|---|---|---|---:|---|
| `kimi-code` | `kimi-membership` | `kimi-for-coding` | `kimi-for-coding` | 262144 | 所有 Kimi Code 会员 |
| `kimi-code-k3-256k` | `kimi-membership-k3-256k` | `k3-256k` | `k3-256k` | 262144 | Moderato 及以上 |
| `kimi-code-k3` | `kimi-membership-k3` | `k3[1m]` | `k3` | 1048576 | Allegretto 及以上可用 1M |

HighSpeed 当前官方模型 ID 为 `kimi-for-coding-highspeed`，官方 Kimi Code 文档已将其列为 Allegretto 及以上可用的现行模型；但它不进入首批稳定范围。Kimi 的独立模型 ID 语义与 Claude Code 官方 `/fast` 不同：后者当前是 Opus 5/4.8 的快速 API 配置，可能切换到 Opus、默认持久化，并在网关场景直连 `api.anthropic.com` 做资格检查。必须在任务卡 8 的真实环境中决定 Kimi HighSpeed 是否加入，且不得把 `/fast` 当作其入口。

### 0.3 允许在没有真实会员 Key 时完成什么

没有真实 Key 时允许完成：

- 官方事实与产品规格更新。
- Provider/Profile/权益元数据 Schema 与配置。
- 独立 Secret、Setup State、菜单、Help、List、Doctor。
- 子进程环境清理、唯一鉴权注入和跨 Profile 隔离。
- 假 Claude 主请求、工具参数、子 Agent 映射、cwd、TTY、信号、退出码测试。
- Mac 本地自动化、Node 18、Windows 模拟、打包清单与敏感信息检查。
- GitHub 功能分支或 Draft PR；执行 push 仍需用户当次明确授权。

没有真实 Key 时不得声称：

- Kimi Code API Key 已验证有效。
- 三个模型都在实际会员档位下可用。
- `/model`、`/effort`、Thinking、compact、工具调用与子 Agent 已通过真实 Provider。
- 请求只消耗会员额度且没有触发 Extra Usage 或开放平台余额。
- `1.5.0` 已满足稳定 Release 门槛。

仓库候选的最高结论只能是：

```text
IMPLEMENTATION CANDIDATE ACCEPTED — KIMI CODE PROVIDER RELEASE BLOCKED
```

## 1. 工作方式与角色合同

### 1.1 固定循环

每张任务卡都使用同一个循环：

```text
用户启动 Luna 执行当前卡
        ↓
Luna 只完成当前卡、运行验证、回写证据
        ↓
用户启动 Sol 审阅当前卡
        ↓
Sol 独立检查、复跑、在当前卡范围内修复并复验
        ↓
Sol 给出 CARD PASS / CARD FAIL
        ↓
只有 CARD PASS 才进入下一卡
```

Luna 和 Sol 都不得自动继续下一张卡。Sol 可以修复本卡内发现的问题；如果修复需要改变产品决策、扩大文件范围、修改真实配置或命中用户红线，必须停止并请求用户决定。

每次 Luna 实施与 Sol 审阅都应在同一个项目工作区上新开会话，继承上一张卡留下的已验收文件状态。不要另建平行 worktree、不要复制仓库、不要在未获用户明确要求时创建 commit；跨会话交接以实际工作区 diff 和本文件证据登记为准。

## 2. 绑定产品与架构决策

### 2.1 独立 Provider、Secret 与账单边界

目标 Provider 合同：

```json
{
  "id": "kimi-code",
  "displayName": "Kimi Code Membership",
  "baseUrl": "https://api.kimi.com/coding/",
  "apiKeyUrl": "https://www.kimi.com/code/console",
  "authVariable": "ANTHROPIC_API_KEY",
  "secretId": "kimi-code",
  "verifiedOn": "<实施当日>",
  "sourceUrl": "https://www.kimi.com/code/docs/en/third-party-tools/claude-code.html"
}
```

禁止行为：

- 不复用或改写 `kimi` Secret。
- 不把 Kimi Code Key 发送到 `api.moonshot.cn`。
- 不把开放平台 Key 发送到 `api.kimi.com/coding/`。
- 不检测 Key 类型，不复制 Key，不在 401/402/403/429 后切换 Provider。
- 不查询或自动开启 Extra Usage。
- 不修改 `~/.claude`、Shell Profile 或系统环境。

### 2.2 订阅权益不能伪装成按量 Pricing

现有 `pricingRef` 表示可核验的按 Token 价格。Kimi Code 是订阅权益与额度通道，不能引用 `kimi-k3` 开放平台价格冒充会员计费。

`1.5.0` 应新增独立权益元数据集合，例如：

```text
config/entitlements/kimi-code-membership.json
```

候选 Schema：

```json
{
  "id": "kimi-code-membership",
  "displayName": "Kimi Code Membership",
  "billingType": "subscription-quota",
  "quotaNotice": "Consumes Kimi Code membership quota; Extra Usage may incur additional charges when enabled.",
  "verifiedOn": "2026-08-12",
  "sourceUrl": "https://www.kimi.com/code/docs/en/kimi-code/membership.html"
}
```

Profile 必须且只能引用一种商业元数据：

```text
pricingRef XOR entitlementRef
```

现有四个 Profile 保持 `pricingRef`；三个 Kimi Code Profile 使用 `entitlementRef`。不为避免 Schema 工作而填入虚假价格、零价格或 `N/A` 价格。

### 2.3 三个 Profile 的完整模型映射

三个 Profile 都把主模型、Opus、Sonnet、Haiku、Fable 与子 Agent 映射到本 Profile 的同一个 Kimi Code 模型，避免后台任务落到 Claude 或其他 Provider。

`kimi-code` 候选环境：

```text
ANTHROPIC_MODEL=kimi-for-coding
ANTHROPIC_DEFAULT_OPUS_MODEL=kimi-for-coding
ANTHROPIC_DEFAULT_SONNET_MODEL=kimi-for-coding
ANTHROPIC_DEFAULT_HAIKU_MODEL=kimi-for-coding
ANTHROPIC_DEFAULT_FABLE_MODEL=kimi-for-coding
CLAUDE_CODE_SUBAGENT_MODEL=kimi-for-coding
CLAUDE_CODE_AUTO_COMPACT_WINDOW=262144
CLAUDE_CODE_MAX_CONTEXT_TOKENS=262144
```

`kimi-code-k3-256k` 候选环境：

```text
ANTHROPIC_MODEL=k3-256k
ANTHROPIC_DEFAULT_OPUS_MODEL=k3-256k
ANTHROPIC_DEFAULT_SONNET_MODEL=k3-256k
ANTHROPIC_DEFAULT_HAIKU_MODEL=k3-256k
ANTHROPIC_DEFAULT_FABLE_MODEL=k3-256k
CLAUDE_CODE_SUBAGENT_MODEL=k3-256k
CLAUDE_CODE_EFFORT_LEVEL=high
CLAUDE_CODE_AUTO_COMPACT_WINDOW=262144
CLAUDE_CODE_MAX_CONTEXT_TOKENS=262144
```

`kimi-code-k3` 候选环境：

```text
ANTHROPIC_MODEL=k3[1m]
ANTHROPIC_DEFAULT_OPUS_MODEL=k3[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL=k3[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL=k3[1m]
ANTHROPIC_DEFAULT_FABLE_MODEL=k3[1m]
CLAUDE_CODE_SUBAGENT_MODEL=k3[1m]
CLAUDE_CODE_EFFORT_LEVEL=high
CLAUDE_CODE_AUTO_COMPACT_WINDOW=1048576
CLAUDE_CODE_MAX_CONTEXT_TOKENS=1048576
```

任务卡 1 于 2026-08-12 重新打开 Kimi Code 官方 Claude Code 接入页后确认：K3-256K 与 K3-1M 的 Fable/Opus/Sonnet/Haiku/Subagent、`CLAUDE_CODE_AUTO_COMPACT_WINDOW`、`CLAUDE_CODE_MAX_CONTEXT_TOKENS` 和 effort 均有直接官方示例。官方只列出 `kimi-for-coding` 的模型 ID、256K 上下文和会员档位，没有给出第三套完整 Claude Code 环境；其候选 Profile 受约束地采用同一完整档位映射、compact/max-context 值并不额外注入 effort，以避免 Claude Code 前后台回落。该推断必须在真实 Provider 验收中验证，不能写成官方直接事实。旧/开放平台 Claude Code 页使用另一套端点、鉴权与模型命名，已在 `docs/07` 登记为不同产品通道的 Blocker，不得混用。

`ENABLE_TOOL_SEARCH=false` 不默认加入。Claude Code 当前对非一方 `ANTHROPIC_BASE_URL` 会默认禁用 Tool Search；只有官方当前接入指南明确要求或真实验收证明需要时，才能先改事实与规格再加入。

### 2.4 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`

Kimi Code 当前官方 Claude Code 示例明确使用该变量。因此任务卡 2 必须：

- 把它加入 Profile 允许变量和 Router 管理变量。
- 每次启动先按大小写不敏感规则清除继承残留。
- 只由需要它的 Kimi Code Profile 回注。
- 移除 Doctor 对它的全局 `legacy/unverified` 结论，改为正常的 Router 冲突检查。
- 验证 Kimi、DeepSeek、GLM 两种模式不会继承该变量。

### 2.5 Claude Code 内模型切换边界

CMR 保持透明启动器：

```bash
cmr kimi-code --model k3-256k
cmr kimi-code-k3 --model kimi-for-coding
```

`--model` 仍作为 opaque argv 传给 Claude Code；CMR 不校验用户会员档位，也不拦截其他 Provider 支持的模型名。

Claude Code 当前把交互式 `/model <name>` 或 picker 的 Enter 写为后续新会话的用户默认；picker 的 `s` 才只切换当前会话。`--model` 与 `ANTHROPIC_MODEL` 只作用于本次启动。CMR 不拦截或改写这些原生行为，但任务卡 5/8 必须核对 `/model` 和 `/fast` 的持久设置不会被误写成 Profile 内临时切换。

稳定推荐仍是“选择一个 CMR Profile 启动新会话”。原因：

- 会话内 `/model` 可能使已建立的缓存失效。
- 从 1M 切到 256K 时可能触发或需要手工 `/compact`。
- 主模型切换不等于后台和子 Agent 映射一定同时改变。
- 没有真实 Key 时不能证明 Claude Code picker 会展示所有 Kimi Code ID。

首版不增加本地代理、动态模型发现、Session Registry 或自制 `/model` 菜单。

### 2.6 Setup 与降级

新增 Provider 后：

- 旧 `seenProviderIds=["deepseek","glm","glm-api","kimi"]` 自然得到 unseen `kimi-code`。
- Full setup 展示五个 Provider；用户可以 `Not now`。
- `cmr setup kimi-code` 与缺 Key inline setup 只操作 `kimi-code`。
- 三个 Kimi Code Profile 共用一个 `kimi-code` Secret，不重复索取 Key。
- Secret Store 与 Setup State 继续使用 Schema v1。

一旦写入 `kimi-code` Secret，手工降级到只认识四家 Provider 的 `1.4.0` 可能拒绝整个 Secret Store。必须在用户文档中说明；不得为降级静默删除新 Key。

### 2.7 官方跳过登录脚本 Blocker

Kimi Code 官方 Claude Code 页要求直接接入用户先运行脚本，写入 `~/.claude.json` 的第三方支持/onboarding 标记并清理 `~/.claude/settings.json` 的旧模型项；Claude Code 官方认证页同时说明设置 `ANTHROPIC_API_KEY` 会跳过登录并提示批准。两份官方资料不能静态证明该脚本对当前版本是否仍是必要条件。

CMR 不运行这段脚本，不修改用户 Claude 配置，也不依赖未公开的持久字段。任务卡 3 必须在隔离 Claude 配置中覆盖环境变量直启路径，任务卡 8 必须在用户授权后真实复核；若仍只能通过持久修改工作，本候选停止并回到产品决策，不得在实现卡顺手越过门禁。
